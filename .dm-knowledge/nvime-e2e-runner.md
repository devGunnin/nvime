- **[invariant]** KILLING THE PROCESS GROUP IS NOT ENOUGH. A big-change runner is spawned `detached: true` (agent/src/detached.ts), so Node calls setsid(): own session, own process group, reparented to init. It is NOT in the scenario's group and a group kill cannot reach it — and `detached` is the default, so EVERY scenario that builds starts one. The only place its pid is written down is the store (session.json `runner.pid`, lock.json `pid`), which is what tests/e2e/runner-pids.mjs reads. Nothing caps a runner's wall clock, so a leaked one drives the real CLI to completion on its own  _(2026-09-03)_
- **[invariant]** A RECORDED PID IS NOT A LIVE PID. `session.runner` is deliberately left behind when a runner exits — that is how bigstore tells "the build died" from "the build is running" — so after every completed build the store still names a dead pid, and signalling it kills whatever recycled the number. The product's own predicate is `liveRunnerFor` + `isLockLive` (agent/src/bigstore.ts, LOCK_STALE_MS 15s): a claim on this host, naming the same pid, heartbeated inside the window. tests/e2e/runner-pids.mjs MIRRORS it (the TS is not importable and the bundle does not export it) with two deliberate narrowings — a foreign-host claim is never signalled (the product returns true there; a killer must not), and a live claim with no session.runner yet still counts so a runner inside its handshake window stays reapable. selftest greps both files so the threshold cannot drift  _(2026-09-03)_
- **[pitfall]** a store record written non-atomically can be read torn, and the e2e reaper treats an unparseable record as a failure (not as "no runners"). bigstore writes tmp+rename for exactly this reason — any test fixture that fakes a record must do the same. Also: build the record's `host` with `uname -n`, never `hostname` (not installed everywhere; an empty host silently makes every claim un-live)  _(2026-09-03)_
- **[pitfall]** `set -m` in a runner script puts each scenario in its own process group, which is what makes a group kill possible — and also means a terminal SIGINT never reaches the scenario. Without an explicit INT/TERM trap, Ctrl-C leaves the whole tree running. Related, when testing that trap: a NON-interactive shell starts background jobs with SIGINT already ignored, so a backgrounded run.sh can never see the signal however correct its trap is — the test harness needs `set -m` too, or it proves nothing  _(2026-09-03)_

1. INTRODUCTION                                            *nvime-introduction*

nvime is a Claude-native Neovim plugin with three capabilities: Chat, Edit and
Big Change. Lua is the UI; a Node sidecar owns every conversation through the
Claude Agent SDK and drives your local `claude` install with its existing
subscription login. No API key is used in any code path.

Big Change is the reason the plugin exists. Claude interrogates the request
into a spec, builds it alone in a disposable clone of the repository, splits
the result into review threads, and grades your written defense of each
substantial one before it will land anything on your branch. There is no
force-merge.

==============================================================================
2. REQUIREMENTS                                            *nvime-requirements*

  - Neovim >= 0.10
  - Node >= 20
  - Claude Code installed and signed in (`claude` on `PATH`)

The sidecar must be built before first use: >

    npm --prefix agent install && npm --prefix agent run build
<
`:Nvime doctor` reports every one of these, with the fix under each failure.

3. SETUP                                                          *nvime-setup*

                                                              *nvime.setup()*
require('nvime').setup({opts})
    Validates {opts} over the defaults, installs them, derives the highlight
    groups from the active colorscheme, and applies the keymaps if they are
    enabled. Raises with the option path that was wrong rather than coercing
    a bad value. Calling it is optional; the defaults apply without it, except
    that no global keymap is bound.

    See |nvime-configuration| for every key.

4. COMMANDS                                                    *nvime-commands*

                                                                     *:Nvime*
:Nvime                  Open the dashboard: what nvime can do, whether it is
                        wired up, and every big change in this project with
                        its review progress. <CR> opens the change under the
                        cursor.

:Nvime chat             Open (or focus) the chat panel. |nvime-chat|

:Nvime edit             Open the edit panel, scoped to the current file.
                        |nvime-edit|

:Nvime big              Open the big-change panel: start a new change, or
                        <C-r> to pick one already going. |nvime-big|

                        change — and say so if none is.

                        big_triage, big_grade, explain), then type/choose its
                        model and reasoning effort — a session-scoped override
                        on top of `models.*` from `setup()` (see
                        |nvime-configuration| for what "session-scoped" means
                        here). Only the field you actually pick replaces the

                        Its effort step's `reset` entry clears the whole

                        scoped enrollment record. Available only when a
                        licensed organization control plane is configured.

:Nvime doctor           Run every preflight check and render the result as one

                        failure. |nvime-health|

:Nvime statusline       Toggle the built-in winbar status on or off, globally,
                        for windows that have no winbar of their own.
                        |nvime-statusline|

:Nvime debug [arg]      Turn the debug log on or off for this session.
                        `on`/`info`, `debug`, `off`, or `toggle` (the default).
                        |nvime-diagnostics|

:Nvime log              Show the tail of the debug log in a readonly split;
                        `q` closes it. `:Nvime log clear` empties the file.

:Nvime bundle           Write everything a bug report needs to one markdown
                        file and copy its path to the `+` and `"` registers.

5. KEYMAPS                                                      *nvime-keymaps*

Global maps are off until `keymaps.enabled = true`. Every mapping nvime
defines is a leaf: none is a prefix of another, so nothing ever stalls for
'timeoutlen'. `:checkhealth nvime` reports this.

Global ~
    <leader>nc      normal      open chat
    <leader>ns      visual      send the selection with its file and lines
    <leader>ne      normal      instruct claude about this file
    <leader>ne      visual      instruct claude about the selection
    <leader>nd      normal      review the changeset
    <leader>nB      normal      open a big change

Prompt buffer ~
    <CR>            normal      send the prompt
    <C-s>           insert      send the prompt (<CR> still inserts a newline)
    <C-c>           both        stop the running turn (chat, edit, big). In
                                 insert it acts without leaving insert — it no
                                 longer drops the box into normal mode
    <C-r>           both        session / change picker (chat, big; the edit
                                 panel has none) — in insert only while the box
                                 is EMPTY; with anything typed it is
                                 |i_CTRL-R|, the register paste, as always
    <C-n>           normal      start a new conversation / big change
    <C-t>           normal      open the review threads (big panel)
    ]o              normal      jump to the pending choice

    Which keys reach into insert mode is decided key by key, never by the
    key's shape. The box is left in insert after every send, so `<C-c>` and
    `<C-r>` answer there; `<C-n>` and `<C-t>` do NOT, because insert mode
    already owns them (|i_CTRL-N| walks the @-path completion popup this very
    box offers, |i_CTRL-T| indents the line). The hint marks a normal-only key
    `n_<key>`. While the completion popup is up, every insert mapping hands the
    key back to Neovim.

Session / change picker ~
    <CR>                        open the row under the cursor
    d                           delete this row (y/n float, chat sessions only)
    q, <Esc>                    close

Scrollback ~
    q                           close the panel

Approval float ~
    y, Y                        allow once
    n, N, <Esc>                 deny

Changeset ~
    <CR>                        open the file at this hunk
    r                           revert this hunk
    d                           toggle the unified diff
    q                           close

Big-change panel ~
    <C-n>                       start a new big change
    <C-r>                       pick a big change
    <C-t>                       open the review threads
    s                           steer the running build (scrollback; typing in
                                 the prompt while it builds steers it too).
                                 Offered only while the sidecar reports the
                                 build steerable — a build that fell back to
                                 running inside the sidecar has no runner to
                                 reach, and says so instead
    <C-c>                       stop the run
    ]o                          jump to the pending choice
    q                           close

Review threads ~
    ]t, [t                      next / previous thread
    ]c, [c                      next / previous hunk in this thread
    t                           toggle the unified diff
    a                           defend this thread (the gate)
    e                           explain a cleared thread
    r                           request changes on this thread
    X                           re-open (or re-clear) a trivial thread
    R                           rebase the build onto a moved base (asks y/n
                                 first when pressed on the file pane)
    M                           merge into your branch (asks y/n first when
                                 pressed on the file pane)
    <C-c>                       give up waiting on a wedged request (does not
                                 stop it — unlike the panel's <C-c>, which
                                 reaches the runner and actually stops the run)
    <CR>                        open this file in the build clone (refused
                                 for any file the review already holds a
                                 buffer of — the pane is that buffer)
    q                           close the review

Dashboard ~
    c, e, b, d                  chat / edit / big / changeset
    <CR>                        open the change under the cursor
    q, <Esc>                    close

Answer box (paste-blocked) ~
    <CR>                        submit
    <C-s>            insert     submit
    <Esc>            both       cancel (one press, from insert too); with the
                                 completion popup up it closes the popup only
    q, <C-c>         normal      cancel
    A cancelled draft is put in the unnamed register: "p pastes it back.
    p, P, gp, gP, ]p, [p, ]P, [P, i_<C-r>   refused: type it

6. CHAT                                                            *nvime-chat*

A persistent, read-only conversation with full session history. Streaming
markdown is rendered as it arrives. nvime classifies every line itself and
paints nothing else over it, so a line never changes colour between streaming
and settled; markup delimiters are concealed, fenced code is set apart by its
own ground, and a `---` separator becomes a short gap marker rather than a
rule across the panel.

Choices ~                                                       *nvime-options*
    When the agent's question is a pick between alternatives rather than an
    open one, it offers them and the panel renders them numbered, inline in
    the conversation — in chat and in big-change intake alike. `1` to `9`
    answers, and a question that takes several answers toggles them and sends
    on <CR> — but only while the cursor sits on the block's own rows;
    anywhere else a digit is the ordinary vim count it always is (`12G` still
    reaches line 12), and <CR> the ordinary line motion. `]o` jumps the
    cursor onto the pending choice from wherever you are, prompt included.
    `o`, or just typing in the prompt, answers in your own words instead, and
    typing the number works too. Your pick reads back into the transcript as
    `-> 2: Environment variable`, so the history still reads as dialogue.

    The digit, <CR> and `o` keys are buffer-local to the panel's scrollback —
    never bound while you are typing in the prompt — and released the moment
    the question is answered or the next turn starts; `]o` is a standing
    panel key, bound for the life of the panel. Intake carries the block in
    its structured output; in chat the model opts in with a fenced
    `nvime-options` block, which the panel swallows rather than showing.

Context ~
    Write `@path/to/file` or `@path/to/dir` in a prompt and nvime attaches it:
    a file as its contents, a directory as a bounded listing. Relative paths
    resolve against the project root the panel was opened on, never Neovim's
    cwd. Bad, binary or oversized paths are reported in the panel rather than
    dropped. `@` completion is gitignore-aware.

Sessions ~
    Opening chat starts a fresh conversation — `chat.default = 'new'`, the
    default; set it to `'resume-last'` to pick this project's most recent
    conversation back up on open instead. <C-r> opens a picker whose first
    row is "new conversation" and whose remaining rows are past sessions by
    title and age (a session with no prompt yet reads as `(new)` plus its
    short id, so two of them are still tellable apart); <C-n> starts another
    clean conversation without deleting history.
    `d` on a picker row deletes that session and its history, after a y/n
    float — never a modal. Resume survives Neovim restarts, and several
    Neovim instances share the session file without overwriting each other.
    Switching is refused while a turn is running, so its stream and
    cancellation handle cannot be orphaned.

Chat can never touch your code: it gets Read, Glob, Grep, WebFetch and
WebSearch, and file mutation and shell are denied through SDK options rather
than prompt text. See |nvime-security| for what that does NOT confine.

7. EDIT                                                            *nvime-edit*

`<leader>ne` scopes the instruction to the current file; from visual mode, to
the selection. The prompt stays armed afterwards, and a follow-up is not
pinned to the original file.

Live application ~
    Every change is pushed to the editor as its exact before/after the moment
    the tool finishes. If a buffer holds that file only the changed hunks are
    rewritten through the buffer API: the cursor and scroll position stay put,
    the changed lines light up and fade after `edit.fade_ms`, and the buffer
    is left unmodified and in step with disk. No `:e`, no reload prompt, and
    no W11/W12 warning later.

    One undo block per run, per buffer: a single `u` reverts everything one
    run did to that buffer. It reverts the BUFFER — disk keeps the agent's
    version until you `:w`.

    A buffer with unsaved edits the agent did not see is refused, not
    overwritten, and the conflict is reported. A file some other writer
    changed in between is reported as `external-change` and left alone.

Approvals ~
    Writes under the project root run unattended. A write anywhere else, and
    any shell command, opens a `y`/`n` float — never a modal, and the editor
    stays usable while it waits. The float carries the whole command or path,
    wrapped over as many lines as it takes; past 8 KB it says how many bytes
    it could not show. An unanswered ask is denied, as is one whose run was
    cancelled. `edit.approval_timeout_ms` bounds the wait.

Changeset ~
    `<leader>nd` lists every file the run touched with its hunks. `<CR>` jumps
    to a hunk, `d` toggles a plain unified diff, and `r` reverts one hunk
    through the same live-application path. A hunk whose lines have been
    hand-edited since refuses to revert rather than writing something neither
    side asked for.

8. BIG CHANGE                                                       *nvime-big*

Intake ~
    Describe the change; Claude reads the repo and asks until it is not
    guessing, then plays back a spec (goal, approach, scope, acceptance, out
    of scope) as schema-enforced structured output. No spec is ever invented
    from prose. Answer, revise, or type `approve`. Typing `vibe`, `easy`,
    `medium` or `extreme` while drafting moves the gate.

    A question with discrete alternatives arrives as a numbered choice you
    pick from with a keypress; see |nvime-options|.

Sessions ~
    Opening the panel starts a new change. <C-r> opens a picker whose first
    row is "start a new change" and whose remaining rows are existing
    sessions; <C-n> does the same from inside the panel. Starting fresh never
    discards an existing session or its build clone — `discard` from the
    picked session's own panel is what throws one away.

Build ~
    Approving records HEAD and returns; the build then makes a local clone of
    the repository at that commit under `stdpath('data')/nvime/big/`, with
    `origin` removed. The build agent works there with full mutation rights
    and is told not to commit. Progress streams into the panel; <C-c> stops
    it.

    The build runs in a DETACHED process of its own, not inside Neovim's
    sidecar: it holds the session's claim, appends every event to an
    append-only `events.ndjson` beside the record, and keeps going when you
    close Neovim. Capture and triage run there too, so a build you walked
    away from ends with its threads ready. Opening the session again — the
    same Neovim, a new one, or two at once — replays that log and then follows
    the runner live over a unix socket in `$XDG_RUNTIME_DIR/nvime`.

    If the runner cannot start, the build falls back into the sidecar with a
    notice saying so, and then really does stop with the editor.
    `NVIME_DETACHED=0` forces that older behaviour. Windows is a non-goal: the
    control channel is a unix domain socket.

Steering ~
    `s` in the build panel opens a compose box; what you type is handed to the
    running build as an ordinary user turn and read at its next turn boundary.
    Nothing is interrupted and nothing is re-run. The stream shows `you →
    build` when the steer is accepted, and again when the agent takes it.

    A steer is context only. It travels inside the same agent session whose
    powers were fixed when the build started, so it cannot widen the write
    boundary, reach the permission callback, or move the review gate.

Triage ~
    On completion the diff against the base is captured and a read-only triage
    turn groups the hunks into threads, rating each substantial or trivial.
    Every hunk lands in exactly one thread; anything triage forgot becomes an
    open `unsorted` thread, and a failed triage falls back to one substantial
    thread per file and says so. Trivia auto-resolves but stays visible with
    an `auto` chip, and `X` re-opens it.

The review pane ~
    Selecting a thread opens the build clone's own copy of the changed file as
    an ordinary buffer: real path, real filetype, treesitter highlighting, and
    your own LSP attaching as it would to any file you opened. It is
    `nomodifiable` and `readonly` — the clone is a sandbox to read, not to
    edit — and that holds for every buffer the pane shows, one you already had
    open included. Such a buffer stays yours: it is handed back listed and
    writable as you had it, while the buffers the review opened itself are
    wiped when it closes.

    `M` and `R` ask a y/n question before they run when you press them on the
    file, where both are ordinary motions. On the thread list they stay
    immediate.

    The diff is extmarks over that buffer, never text: changed and added rows
    carry a band, removed lines render as dim virtual lines above whatever
    replaced them, and the thread's question and graded rounds hang at its
    first hunk. `]c`/`[c` walk the thread's hunks, switching file when it
    spans more than one.

    `t` toggles the plain unified diff for pure patch reading. A thread with
    no file to annotate — binary content, a deleted file — falls back to it on
    its own, and so does a build clone that is gone, which says so once. So
    does a file that has moved on since the capture: one line per hunk is
    checked against the buffer before anything is drawn, and a hunk offering
    no such line is not drawn at all. A file you already have open in another
    tab falls back too — that window is left alone, and `<CR>` goes to it.

The gate ~
    `a` on an open substantial thread opens an answer box that takes typed
    text only. Submitting runs one read-only grading turn in the build clone,
    resumed across rounds. Under the pass mark the thread stays open and the
    grader's hint and follow-up render in it; the next answer has to address
    the follow-up. There is no round cap and no override.

    Pass marks: `vibe` no gate, `easy` 40, `medium` 70, `extreme` 90.

    If the grading turn fails or answers unusably the round is recorded
    ungraded: the answer is kept, the thread stays open, and the pane says
    why. A grade nobody gave is never inferred.

Merge ~
    `M` lands the reviewed change on the branch the build started from — the
    only thing nvime ever writes to your repository. It asserts every
    precondition itself and reports all of them at once. The commit is built
    in a private index outside the repository, so an interruption leaves your
    index, tree and branches exactly as they were; exactly one command touches
    your checkout, `git merge --ff-only`, and HEAD is re-read immediately
    before and after it.

    `R` rebases the build onto a base branch that has moved, then re-captures
    and re-triages; content already defended carries forward by signature.

9. CONFIGURATION                                          *nvime-configuration*

Defaults: >

    require('nvime').setup({
      panel = {
        width = 80,
        prompt_height = 3,
        position = 'right',
      },
      ui = {
        icons = 'unicode',
      },
      keymaps = {
        enabled = false,
        chat = '<leader>nc',
        send_selection = '<leader>ns',
        edit = '<leader>ne',
        changeset = '<leader>nd',
        big = '<leader>nB',
      },
      chat = {
        default = 'new',  -- or 'resume-last'
      },
      edit = {
        fade_ms = 1500,
        nofade = false,
        approval_timeout_ms = 60000,
      },
      big = {
        difficulty = 'medium',
        cleanup_on_merge = false,
      },
      agent = {
        node = 'node',
        claude = nil,
        request_timeout_ms = 15000,
      },
      models = {
        chat = { model = nil, effort = nil },
        edit = { model = nil, effort = nil },
        big_build = { model = nil, effort = nil },
        big_intake = { model = nil, effort = nil },
        big_triage = { model = nil, effort = 'medium' },
        big_grade = { model = nil, effort = 'medium' },
        explain = { model = nil, effort = nil },
      },
      context = {
        max_file_bytes = 200 * 1024,
        max_dir_entries = 200,
      },
      project_instructions = {
        enabled = true,
      },
      organization = {
        control_plane_url = nil,
        trust_core = nil,
        github = 'gh',
      },
    })
<
panel.width            number, 20..400. Columns the panel occupies.
panel.prompt_height    number, 1..20. Lines of the prompt buffer.
panel.position         'right' or 'left'.

ui.icons               'unicode' (default) or 'ascii'. The default set uses
                       only plain Unicode — box drawing, arrows, a check mark,
                       quarter-circle spinner frames — never a private-use
                       Nerd Font codepoint. 'ascii' swaps the whole set.

keymaps.enabled        boolean. nvime binds no global key until this is true.
keymaps.chat           string, `<leader>nc` by default.
keymaps.send_selection string, `<leader>ns` by default.
keymaps.edit           string, `<leader>ne` by default.
keymaps.changeset      string, `<leader>nd` by default.
keymaps.big            string, `<leader>nB` by default.

chat.default           'new' (default) or 'resume-last'. What opening chat
                       with no prior selection does: start clean, or pick
                       this project's last conversation back up.

edit.fade_ms           number >= 100. How long a fresh hunk stays lit.
edit.nofade            boolean. Keep the highlight until the next change.
edit.approval_timeout_ms
                       number >= 1000. How long the sidecar holds a tool call
                       waiting for your y/n before denying it.

big.difficulty         'vibe' | 'easy' | 'medium' | 'extreme'. The gate a NEW
                       big change starts with.
big.cleanup_on_merge   boolean. Throw the build clone away once the change
                       lands. Off by default: the clone is the only place the
                       build's own history still exists.

agent.node             string. The node binary; `~` is expanded. Not
                       executable? setup() warns and carries on — `:Nvime
                       doctor` is where that is diagnosed.
agent.claude           string or nil. Absolute path to `claude`; nil resolves
                       it from PATH.
agent.request_timeout_ms
                       number >= 1000. Deadline for control requests. A
                       streaming turn is exempt: it is bounded by your stop
                       key, not a timer.
                       `agent.model` was replaced by `models.<lane>.model`
                       below; `setup()` refuses the old key outright rather
                       than silently ignoring it.

models.{lane}.model    string or nil, for each of `chat`, `edit`, `big_build`,
                       `big_intake`, `big_triage`, `big_grade`, `explain`. A
                       model id or alias (e.g. `claude-opus-5`, `haiku`); nil
                       uses the CLI's own default. Not whitelisted: any string
                       passes through to the SDK unchanged. `big_triage` is the
                       exception: an unset `big_triage.model` uses `big_build`'s
                       model, not the CLI default, so a build lane pinned to a
                       cheaper model silently triages on it too unless
                       `big_triage.model` is set explicitly.
models.{lane}.effort   'low' | 'medium' | 'high' | nil. Reasoning effort for
                       that lane; nil uses the CLI default. `big_triage` and
                       `big_grade` are different: triage decides what the gate
                       reviews and grading IS the gate, so neither may be
                       'low' — `setup()` raises if either is configured that
                       way — and neither's effort defaults to nil; an unset
                       one names 'medium' rather than silently inheriting the
                       shell's own effort (e.g. `CLAUDE_CODE_EFFORT_LEVEL`).
                       `:Nvime model` sets a SESSION-SCOPED override on top of
                       these, per lane — "session" here means this Neovim
                       session: the override lives in memory, survives a
                       sidecar restart, and is gone once you quit. Only the
                       field you actually choose replaces the configured one
                       (picking 'default' for the other keeps it); see
                       |nvime-commands|.

context.max_file_bytes number >= 1024. Ceiling on one `@file` attachment.
context.max_dir_entries
                       number >= 1. Ceiling on one `@dir` listing.

project_instructions.enabled
                       boolean. Send CLAUDE.md / AGENTS.md / .nvime/
                       instructions.md to chat and edit as an explicitly
                       marked-untrusted block. Off disables reading the file
                       at all.

organization.control_plane_url
                       string or nil. Licensed organization policy and
                       attestation endpoint. Must use HTTPS, except loopback
                       HTTP for local development.
organization.trust_core
                       string or nil. Absolute path to the native licensed
                       nvime-trust signer. It must be configured together with
                       control_plane_url.
organization.github    string. Authenticated GitHub CLI executable; `gh` by
                       default. Managed certification resolves live numeric
                       user and repository IDs through it.

10. HIGHLIGHT GROUPS                                         *nvime-highlights*

Colours are derived from the active colorscheme at runtime and re-derived on
|ColorScheme|. Only foregrounds are read: every background nvime paints is
that foreground blended into your own `Normal` background at a low alpha, so
the tints work on a light background and on a colorscheme whose diff groups
have a neutral background.

Override any of them after `setup()` with |nvim_set_hl()|.

    NvimeUser           your own turns
    NvimeAgent          the agent's turns
    NvimeUserBody       your prose's full-line surface
    NvimeAgentBody      the agent prose's full-line surface
    NvimeTool           tool activity between streamed prose
    NvimeHeading        markdown headings, page titles
    NvimeCode           a fenced code block's background
    NvimeFence          the fence lines around it
    NvimeInlineCode     `inline code`
    NvimeBold           **bold**
    NvimeItalic         _italic_
    NvimeDim            secondary text
    NvimeActivity       the next step a surface suggests
    NvimeError          failures and refusals
    NvimeSession        session and state markers
    NvimeSelected       the row a picker's cursor is on
    NvimeBar            a panel's winbar
    NvimeBarDim         a hint bar
    NvimeBarKey         a key named on a bar
    NvimeCursorLine     the cursor line inside nvime's own windows
    NvimeLabel          a label left of the value it names
    NvimeKey            a key the reader is meant to press
    NvimeOk             a passing check, a clearing grade
    NvimeWarn           a warning, a grade that was not enough
    NvimeFile           a file name in a list
    NvimeAdded          an added hunk's sign
    NvimeChanged        a changed hunk's sign
    NvimeRemoved        a removed hunk's sign
    NvimeThreadDefend   the DEFEND chip
    NvimeThreadClear    the ok chip
    NvimeThreadAuto     the auto chip
    NvimeThreadOpen     the OPEN chip on a re-opened trivial thread
    NvimeEditAdd        a freshly added hunk's band

11. STATUSLINE                                               *nvime-statusline*

                                                       *nvime.statusline()*
require('nvime').statusline()
    A compact string for your own 'statusline': `nvime: chat ●` while a chat
    turn streams, `nvime: edit N hunks` while a run applies them, `nvime: big
    X/Y defended` for the selected big change (or `nvime: big building` while
    one is still being built). Appended with `  <lane>:<model>/<effort>` for
    every lane whose model dial is off the CLI default (config or a `:Nvime
    model` override) — e.g. `nvime: big_build:opus/high`. Empty when there is
    nothing to report and every lane is at its default. Reads only what each
    surface already keeps live — never a fresh request, never a timer. >

        vim.o.statusline = "%f %m %= %{v:lua.require('nvime.statusline').get()}"
<
`:Nvime statusline` toggles a built-in 'winbar' equivalent instead, for
windows that have no winbar of their own.

12. HEALTH                                                       *nvime-health*

`:Nvime doctor` and `:checkhealth nvime` run the same checks:

    - Neovim version
    - the keymaps are leaf-only
    - node, and its version
    - the sidecar is built, and answers a ping
    - the `claude` CLI, and its version
    - no API key or provider override is in the environment
    - a claude credentials file exists (best effort)
    - this repository has a git identity, which a local merge needs
    - which lanes, if any, run a non-default model/effort dial
    - the debug log's level, path and size |nvime-diagnostics|

`:Nvime doctor` renders them as one pass/warn/fail list with the fix named
under each failure; `q` or `<Esc>` closes it.

13. DIAGNOSTICS                                             *nvime-diagnostics*

When something is stuck, these three make it reportable. All of it is local,
none of it costs a token, and nothing runs until you turn it on.

The debug log ~
    Off by default, and free when off: the level is the first thing every log
    call checks, so a streamed token costs nothing at all. Turn it on for good
    in `setup()` >

        require('nvime').setup({ debug = { level = 'info' } })
<
    or for this session with `:Nvime debug on`. Levels:

        off     nothing at all (the default)
        info    one line per RPC request, reply and event, plus every state
                transition in big/edit/chat — display and phase changes,
                approvals, steers, and the merge precondition check
        debug   the same, plus the streamed deltas

    It is written to `stdpath('log')/nvime-<pid>.log` (`stdpath('state')` on a
    Neovim without a log directory) — one file per process, because two
    editors sharing one file rotate over each other's history silently.
    Append-only, created 0600, rotated at 5 MB keeping one `.1`, and pruned
    once a week-old file belongs to an editor that is gone. The sidecar
    mirrors its own half into its editor's file, so both ends of a stuck run
    read as one timeline — with one exception: a detached build's runner is a
    separate process and does not mirror.

    What never reaches it: what you typed, your files' contents, and anything
    in a field named like a secret. Content-bearing fields are recorded as a
    size (`<412 chars>`, or `<5 keys, 251 bytes>` for an object), secret-named
    ones as `<redacted>`, and title-derived names — a big change's `title`, its
    `branch`, any `slug` of one — as a size too, since a branch is
    `nvime/big/<slug of the title>` and a title is the first 80 characters of
    your prompt. The approved spec goes the same way, as `spec` and as each of
    its fields (`goal`, `approach`, `scope`, `acceptance`, `outOfScope`), since
    a spec can arrive unwrapped. A field named as content is recorded by its
    size WHATEVER it holds — never walked into. So do the smaller things you
    write: `answer`, `followup`, an offered choice's `label`/`detail`, and the
    `entries` of a directory you attach — the clip is a budget, not a
    redactor, and a short field nobody named would fit inside it whole. Every
    payload is clipped at a character boundary. That is what makes the log safe to paste into a public
    issue, and it has to hold at the log line: `:Nvime bundle` attaches the
    tail verbatim.

:Nvime log ~
    Opens the last 200 lines in a readonly scratch split, parked at the newest
    line — every process's log merged by timestamp, the rotated `.1` included.
    `q` or `<Esc>` closes it. `:Nvime log clear` empties this process's file,
    never another editor's, and re-renders an open split.

:Nvime bundle ~
    Writes one markdown file under `stdpath('cache')`, 0600, and copies its
    path to the `+` and `"` registers. It carries the nvime version and git
    sha, your Neovim, OS, node and claude versions, your configuration with
    secrets redacted, the `:Nvime doctor` output, the last 200 log lines, and
    — when a big change is selected — its session and the last 50 events from
    its build log. Nothing blocks: every probe it makes — node, git, the
    claude version — runs off the main thread with a 3 s deadline and prints
    `(timed out)` rather than waiting, and no second sidecar is started.

    THE BUNDLE PRINTS WHAT IT NAMES, NEVER WHAT IT IS HANDED. Every section is
    an allow-list. The session the sidecar sends carries the runner's control
    token and socket, the spec, the conversation, and a title that is the
    first 80 characters of what you typed; the bundle prints id, state,
    display, steerable, base and head sha, the worktree path, the runner's pid
    and whether it is still alive, and the timestamps — nothing else. Run-log
    events are the same: a delta becomes a byte count, a tool its name and a
    summary length, a phase its phase, and anything unrecognised its key
    names.

A merge check that runs long ~
    While the review tab is checking the merge preconditions the bars carry a
    spinner and what is running, so a slow check is visibly in progress rather
    than indistinguishable from a wedged editor. Past 30 seconds it says so
    and names `:Nvime bundle`.

14. SECURITY MODEL                                             *nvime-security*

nvime is precise about what it confines. The README carries the full text;
the short version:

Subscription only ~
    Every variable the SDK reads to supply a credential, redirect the
    endpoint, or select another provider is stripped from the environment the
    SDK sees, and `:checkhealth` says which of them were set. Proxy and TLS
    variables are deliberately left alone, which means a configured
    man-in-the-middle still sees the traffic.

Managed assurance ~
    A managed Big Change is pinned to the live immutable organization policy
    and exact gate threshold. After merge, the sidecar verifies HEAD, resolves
    numeric GitHub identity, and asks the native Ed25519 trust core to sign
    canonical evidence. The private key never enters Lua or Node. There is no
    shared submission token in the plugin; the server requires a paid
    entitlement and an enrolled repository-scoped public key, then the PR
    webhook binds stored evidence to the exact pushed head.

No project settings ~
    Chat and edit load no `.claude/settings.json` — not the repo's, not
    yours. Its hooks would run shell on the model's first Read, and its
    `env`/`apiKeyHelper` would put back the credentials nvime just stripped.

Reads are NOT confined                                *nvime-security-reads*
    Read, Glob, Grep, WebFetch and WebSearch are always allowed and are not
    confined to the project root. Read any file you can read, then WebFetch an
    attacker's URL, is a complete exfiltration path with no approval prompt in
    it. The realistic trigger is prompt-injected content in a repository you
    opened. This is a deliberate tradeoff and cannot currently be turned off.
    The write gate is unaffected.

A big-change build is only mostly confined ~
    Its git commands, and file writes by Edit/Write, stop at the clone. Shell
    can reach anywhere — `cd` costs nothing — and the clone's object database
    is hardlinked to yours, so a raw write under `.git/objects` can corrupt
    your repository. Nothing asks during a build: a build outlives the editor,
    so the fail-safe answer with nobody watching is no.

The build's control socket ~
    A detached build serves a unix socket under `$XDG_RUNTIME_DIR/nvime` (or
    a per-uid directory in the system temp dir), created 0700 and refused if
    it is not a real directory this user owns; the socket itself is 0600.
    Every frame must also carry a per-run token kept only in the 0600 session
    record, so watching, steering or stopping a build takes more than running
    as your uid — it takes read access to your nvime store. Anything with
    that reach, the build agent's own Bash included, can steer or stop the
    build. Steers are recorded with the editor that sent them, so a second
    editor's shows as `another editor → build`, never as yours.

The paste block is a block, not a sandbox ~
    The answer box refuses the put mappings, refuses |vim.paste()|, and undoes
    any burst that arrives by another route. Text fed in slowly enough gets
    through. The grader still grades what you submit.
